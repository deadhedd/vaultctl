### 🟡 Abort reports success for an unfinished revert or sequencer, `internal/vaultctl/sync.go:447`
**Problem**: `detectOperation` now identifies `REVERT_HEAD` and `sequencer`, so `syncStart` tells the operator to use `vaultctl sync --abort`. But `syncAbort` has no branch for either state and falls through to the successful no operation message, leaving the operation in place.
**Why it matters**: An operator following the reported recovery path remains blocked from normal sync, while the command claims there was nothing to abort. This is especially confusing because the change added these markers specifically to reject incomplete repository states.
**Suggested fix**: Either invoke the appropriate Git abort command for revert and sequencer operations, or return a clear error that directs the operator to the supported raw Git recovery command. Add a regression test that creates each marker and verifies the resulting recovery behavior.
